# Bilingual Documentation Specification / 双语文档规范

## Purpose / 目的

<!-- EN: -->
This document establishes the bilingual documentation standard for the Bootstrap project. All project documentation, including OpenSpec artifacts (proposals, designs, specs, tasks), MUST be written in both English and Chinese.

<!-- CN: -->
本文档为 Bootstrap 项目建立双语文档标准。所有项目文档，包括 OpenSpec 制品（提案、设计、规范、任务），必须使用英文和中文两种语言编写。

---

## Rationale / 理由

<!-- EN: -->
1. **AI Model Understanding**: English documentation ensures AI models (like Claude, GPT) can accurately understand and process project specifications and implementation details.

2. **Human Understanding**: Chinese documentation allows Chinese-speaking developers to quickly grasp design thinking and business context.

3. **Consistency**: Maintaining both languages ensures consistent understanding across all stakeholders.

<!-- CN: -->
1. **AI 模型理解**：英文文档确保 AI 模型（如 Claude、GPT）能够准确理解项目规范和实现细节。

2. **人类理解**：中文文档让中文开发者能够快速理解设计思想和业务背景。

3. **一致性**：保持两种语言确保所有利益相关者理解一致。

---

## Format Requirements / 格式要求

### General Guidelines / 通用指南

<!-- EN: -->
- Use HTML comments `<!-- EN: -->` and `<!-- CN: -->` to separate English and Chinese text
- Place English text first, followed by Chinese text
- For code comments, use `// EN:` and `// CN:` prefixes
- Maintain consistent formatting across both languages

<!-- CN: -->
- 使用 HTML 注释 `<!-- EN: -->` 和 `<!-- CN: -->` 分隔英文和中文文本
- 英文文本在前，中文文本在后
- 对于代码注释，使用 `// EN:` 和 `// CN:` 前缀
- 保持两种语言格式一致

### Example Format / 示例格式

```markdown
## Heading / 标题

<!-- EN: -->
English description here.

<!-- CN: -->
中文描述在这里。

- **EN** <!-- EN: -->English point <!-- CN -->中文要点
- **CN** <!-- EN: -->Another English point <!-- CN -->另一个中文要点
```

## Document Types / 文档类型

### 1. OpenSpec Artifacts / OpenSpec 制品

<!-- EN: -->
All OpenSpec artifacts MUST be bilingual:

<!-- CN: -->
所有 OpenSpec 制品必须是双语的：

#### proposal.md / 提案文档

<!-- EN: -->
- Why (background and motivation)
- What Changes (specific changes)
- Capabilities (new and modified)
- Impact (affected areas)

<!-- CN: -->
- Why（背景和动机）
- What Changes（具体变更）
- Capabilities（新增和修改的能力）
- Impact（影响范围）

#### design.md / 设计文档

<!-- EN: -->
- Context (project background, constraints, stakeholders)
- Goals / Non-Goals
- Decisions (with rationale and alternatives)
- Risks / Trade-offs
- Migration Plan
- Open Questions

<!-- CN: -->
- Context（项目背景、约束条件、利益相关者）
- Goals / Non-Goals（目标与非目标）
- Decisions（设计决策及理由、替代方案）
- Risks / Trade-offs（风险与权衡）
- Migration Plan（迁移计划）
- Open Questions（开放性问题）

#### specs/*.md / 规范文件

<!-- EN: -->
Each spec file MUST include:
- Requirements (with Chinese and English descriptions)
- Scenarios (bilingual WHEN/THEN/AND clauses)

<!-- CN: -->
每个规范文件必须包含：
- Requirements（带中英文描述）
- Scenarios（双语 WHEN/THEN/AND 子句）

#### tasks.md / 任务清单

<!-- EN: -->
- Task descriptions in both languages
- Checkbox format for tracking
- Ordered by dependency

<!-- CN: -->
- 中英双语的任务描述
- 用于追踪的复选框格式
- 按依赖顺序排列

```java
     * CN: 创建订单前验证库存可用性
     */
    public Order createOrder(OrderRequest request) {
        // Implementation / 实现
    }
}
```

## Quality Standards / 质量标准

<!-- EN: -->
### Translation Quality

1. **Accuracy**: Chinese translation must accurately convey the meaning of the English text
2. **Context**: Maintain appropriate context for technical terms
3. **Completeness**: Both languages must be complete and equivalent in content

### Formatting Quality

1. **Alignment**: Corresponding sections in both languages should be aligned
2. **Consistency**: Use consistent terminology across all documents
3. **Readability**: Both languages should be easy to read and understand

<!-- CN: -->
### 翻译质量

1. **准确性**：中文翻译必须准确传达英文文本的含义
2. **上下文**：为技术术语保持适当的上下文
3. **完整性**：两种语言必须完整且内容等价

### 格式质量

1. **对齐**：两种语言的对应部分应该对齐
2. **一致性**：在所有文档中使用一致的术语
3. **可读性**：两种语言都应该易于阅读和理解

## Exceptions / 例外情况

<!-- EN: -->
The following situations may allow single-language documentation:

1. **Inline Code Comments**: Simple comments may use a single language
2. **Log Messages**: Runtime log messages may use a single language
3. **Third-party Documentation**: External dependencies' documentation

<!-- CN: -->
以下情况可能允许单语言文档：

1. **内联代码注释**：简单注释可以使用单一语言
2. **日志消息**：运行时日志消息可以使用单一语言
3. **第三方文档**：外部依赖的文档
